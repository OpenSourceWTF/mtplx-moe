# Code audit — 2026-07-18

Audit of `mtplx/` + `scripts/` on the issue-51 line (194 modules / 162k lines,
87 scripts / 30k lines, 161 test files). Recorded here so the findings survive
the session that produced them.

**Status key:** ✅ fixed in this pass · ⬜ identified, not fixed · ✔ verified by
hand · ~ reported by audit, not independently re-verified

Baseline hygiene is genuinely good: 0 bare `except:`, 0 mutable default args,
0 unreachable-after-return, 6 assert-free tests out of 3024. The rot is
concentrated in thread safety, a native type confusion, and env-flag sprawl.

---

## Tier 1 — correctness

### 1. ✅✔ `pin_claims` mutated without `slot.condition` — silently wrong expert

`mtplx/expert_slots.py`, `_complete_slot_claim`.

Removed from `slot.pin_claims` without the lock, while the generation thread
appends under the lock and recomputes `slot.pins = sum(item.active for item in
slot.pin_claims)`. CPython lists don't raise on concurrent modification, so the
sum can miss the just-appended claim and publish `slot.pins == 0` while a pin
is live. `_prepare_load`'s `if slot.pins:` then refills a buffer a live
`ExpertSlotBinding` still points at — wrong expert in the matmul, no exception,
no metric.

Fixed. Lock order was already established by `_release_physical_claim` on the
same path, so no deadlock risk. **Not reproduced under load** — wants a second
pair of eyes.

### 2. ⬜~ `prefetch()` type confusion on the *default* config

`mtplx/native/mmap_mlx.cpp`. `mmap_u32(wired=True)` builds an `mx::array` over
a raw mmap pointer with no `MTL::Buffer`; `prefetch_arrays` unconditionally
casts to `MTL::Buffer*` and calls virtual `->contents()`. `mmap_island_wired`
defaults **True** (`expert_runtime.py:186`) and `models/expert_mlx.py:2371`
calls `prefetch_all()` unconditionally at open.

Any run with `--mmap-island-layers` sends an ObjC message to a pointer that is
the first 8 bytes of expert weight data interpreted as an `isa`. `nb::inst_ptr`
is unchecked, so the boundary cannot catch it. Only the *unwired* flavor is
tested (`tests/test_banked_islands.py:526`).

This is the concrete mechanism behind the standing "prefetch unwired ⇒
metal-mmap never fairly benchmarked" note: **prefetch is only survivable on the
slow arm.** Fix: tag the array flavor and have `prefetch_arrays` skip
non-Metal-backed arrays.

### 3. ✅✔ MTP payload guard exists in one copy of five (step3p5 refuted)

`glm_mtp_patch.py` checks for a complete payload. `deepseek_`, `mimo_`, and
`nemotron_h_mtp_patch.py` only tested `if not mapped:` and loaded with
`strict=False`. A prefix-mismatched checkpoint yields a non-empty `mapped` from
stray keys with zero real MTP tensors → injection reports success → the model
runs with a **randomly-initialised draft head**. `validate_mtp_support` checks
structure, never that weights loaded. Acceptance rate is a primary bottleneck
here, so this degrades throughput with no error surface.

Fixed in those three, with required keys grounded in each module's actual MTP
layer class rather than copied from glm (mimo uses token/hidden_layernorm +
input_proj; nemotron_h has only `norm`/`mixer` unconditional).

**`step3p5` is REFUTED** — it already has `_validate_mtp_load_coverage` (exact
key-set + shape equality, raising) and loads with `strict=True`, which is
strictly stronger than the glm guard the audit wanted ported into it. The audit
was wrong on both the guard and the `strict=` claim.

### 4. ✅✔ rANS infinite loop on a zero-frequency byte

`mtplx/expert_rans.py:182-188` (scalar), `:290-301` (vectorized). `x_max =
x_max_base * f`; `f == 0` → `while x >= 0:` never terminates.
`table_from_freq` documents `freq >= 1` but never enforces it. Encoding a
corpus against a table built from a *sample* — the module's own documented
model — hangs and exhausts RAM.

### 5. ✅✔ rANS silent 4 GiB directory wrap, shipping encoder only

`expert_rans.py:324` — `astype(np.uint32)` wraps silently; the scalar reference
at `:235` raises. The two are documented and tested as bit-identical and
diverge exactly at the boundary, on the shipping side. `deserialize_component`'s
`directory.max()` check passes on wrapped values, so a >4 GiB bank decodes
plausible garbage. C7 is ~64.6 GiB of Q2 experts, so this is reachable.

### 6. ✅✔ `StreamedBatchRunner` re-introduces the lm_head fp32-cast trap

`mtplx/streamed_batch.py:478-480` is the only site casting the lm_head *input*
rather than the logits, and it calls `model.lm_head` directly rather than
`_logits_head()`. Consequences: breaks the module's own byte-identical claim
when `enable_lm_head_fp32=True`; under `MTPLX_HY3_LM_HEAD_QUANT_BITS` the head
is bf16 or q4 depending on whether an AR generation ran earlier in the same
process; and the concurrency benchmark pays a per-step fp32 weight
materialization the AR path doesn't, making AR-vs-batch comparisons unfair.

The determinism test never sets the flag (defaults `False`) — the bug is
precisely in the untested branch.

### 7. ✅✔ Q4→Q2 conversion has no fidelity floor

`mtplx/hy3_expert_q2.py` — five validation sites check only `math.isfinite`.
The sibling converter defines and enforces `Q4_MIN_ROUNDTRIP_COSINE = 0.99`
(`glm52_mtp_artifact.py:54`); hy3 dropped it. A projection at cosine 0.02
converts, journals, pilots, and publishes `"passed": True`. Worse, a **zero**
projection is reported as `cosine=1.0, error=0.0`.

### 8. ✅ Two verifications that don't verify (one REFUTED)

- ~~`expert_q1.py:611` `verify_q1_against_source` ... `tests/test_expert_q1.py:77`
  does not iterate~~ — **REFUTED 2026-07-18.** Line 77 is the *inner* line of a
  `list(...)` call spanning 76-78; the test consumes the generator and asserts
  `len == 2`. Line 184 likewise. Every caller iterates correctly. This was a
  line-number citation read without its surrounding context — my error, and
  exactly the failure mode this document warns about. No change made.
- `hy3_expert_q2.py:4699` — in shallow mode `actual_sha256` is assigned
  `expected_shard.sha256`, so the later `parsed_shard.sha256 !=
  expected_shard.sha256` compares a value to itself and can never fire. Header
  checks still fire; the **payload** hash check is a no-op with `deep=False`.

### 9. ⬜~ q1 resume mislabels experts, and the hash check ratifies it

`expert_q1.py:327-352` — resumed records are labelled from the *current*
`selected` list while the bytes came from a previous run's. The hash is
recomputed from disk rather than compared, so `read_q1_record` validates the
mislabelled record forever. Resuming with a changed `layers=` set permanently
and silently corrupts the artifact.

## Tier 2 — env/flag parsing

**458 distinct `MTPLX_*` vars; 436 undocumented (95%).** There is no central
env parser: 16 independently-defined boolean helpers, 11 numeric, and five
mutually incompatible "off" vocabularies. `mtplx/env.py` is *not* an env module
— it collects reproducibility snapshots.

Notably, **three of the twelve documented vars carry defects** — the documented
surface has a higher defect rate than the undocumented one.

| Flag | Defect |
| --- | --- |
| `MTPLX_SESSION_BLOCK_PREFIX_RESTORE` ⬜~ | 4 readers, 3 semantics. Unset means ON in `generation.py`/`engine_session.py`, OFF in `session_bank.py:838`. `server/openai.py` is allowlist-based so `=enabled` turns it OFF. Masked on the CLI path; bites library embedders. |
| `MTPLX_PAGED_KV_QUANT` ⬜~ | `8`/`8bit`/`uint8` → normalize, raise, or **silently pick the wrong KV layout** across three readers. |
| `MTPLX_LOOP_GUARD` ⬜~ | Reuses a lease-disabled allowlist containing `"unlimited"`. `=none`/`=unlimited` → server reports guard off, `loop_guard.py:171` builds it on. |
| `MTPLX_SKIP_VERIFY_SNAPSHOT` ⬜~ | Read site is default-OFF but the shipped fast path force-sets `"1"`; correctness is restored only by a two-element strategy allowlist. **Any new verify strategy silently inherits skip-ON.** |

Also: `--chat-template-profile` uses `or` where nine sibling gates use
override-only-when-not-typed, so an explicitly typed value is silently
rewritten on gemma4 (`server/openai.py:24051`). And neither parser sets
`allow_abbrev=False` while explicit-flag detection records raw token text, so
`--mod foo` parses into `args.model` but isn't seen as explicit — affecting
~30 `cli_flags` checks. `--no-fanmax` is defined but never read: it does not
negate `--fanmax`.

## Tier 4 — duplication

**MTP patches: 8 modules, 5,201 lines.** glm↔deepseek are 82% identical
whole-file, `mtp_forward` 96.4% (differing only in an error-message model
name). 273 byte-identical lines across 8 functions plus ~133 near-identical —
~406 redundant lines, ~20% of the 2,010-line cluster. **This copy-paste

**`position_offset` is accepted and silently dropped in 7 of 8 MTP modules** —
consumed only by `mtp_patch.py`. `MTPLX_MTP_POSITION_MODE` is therefore a

but the embedded Metal source strings duplicate heavily: the R2 sigmoid +
expert-bias + top-8 election block is reimplemented three times at 70-84%
similarity, plus three copies of the same 4-line sigmoid helper.

## Tier 5 — issue-51 line specifically

- **The roofline profiler distorts the forward it profiles.** The module
  docstring claims captures are "cheap; no timing there, so the forward is
  undistorted", but `_concrete` and `snapshot_cache` both call `mx.eval` — a
  host sync on two large KV arrays — from inside the live forward. The
  `snapshot_cache` fix correctly stops the profiler advancing the live KV
  cache, but each snapshot is still mutated ~8× during `_queued_seconds`, so
  the "avoids step-256 boundary reallocation" claim is mitigated, not
  eliminated.
- **`self._mtplx_draft_lm_head = cached`** registers a full head in MLX's
  module tree. Verified on MLX 0.31.2: excluded from `parameters()` but
  **included in `children()`, `leaf_modules()`, `state`, `apply_to_modules`** —
  so `nn.quantize` and state serialization walk a ~278 MB shadow head.
- **QKV fusion silently disables two subsystems.** With
  `MTPLX_FUSE_HY3_QKV_PROJECTIONS=1`, `self_attn.q_proj` no longer exists, so
  `kernel_selfcheck.py:444` and `graphbank.py:993` fall through to `None` for
  hy3 — skipping the selfcheck and the compiled-verify bits gate. The pack
  itself is correct.
- **Three env-parsing conventions in one feature**, and both quant flags do an
  `os.environ.get` on **every token**. `MTPLX_HY3_LM_HEAD_QUANT_BITS` uses raw
  `int(...)`, so `=true` raises `ValueError` **mid-forward**, and bits are
  never validated against {2,3,4,6,8}.
- **The speculative-sampling correctness oracle tests an unused module.**
  `mtplx/speculative.py` has zero importers, and `verify_one_token` /
  `acceptance_probability` / `residual_distribution` /
  `speculative_output_marginal` are called only by tests. So
  `test_speculative_output_marginal_recovers_target_distribution` proves the
  correctness of a reference implementation the shipped decoder does not use.

## Tier 6 — tests

Suite is green: **3818 passed, 17 skipped, 0 failed** (full run, 2026-07-18,
with `PYTHONPATH` set to the worktree).

**Gotcha worth knowing:** running the suite in a *worktree* without
`PYTHONPATH` gives 4 spurious failures in `test_glm52_mtp_artifact.py`. The
shared venv resolves `mtplx` to the main checkout for **subprocess** tests;
in-process tests pass because pytest's `pythonpath = ["."]` puts the worktree
first. Set `PYTHONPATH=$PWD`.

**No marker system exists** — `pyproject.toml` has no `markers`, no
`--strict-markers`. Gating is ad-hoc per file, and this machine defeats nearly
every gate (mlx/mlx_lm/fastapi all import, Metal available). A bare `pytest`
here runs 3,829 tests including full GPU dispatch and model loads.

Gaps:
- **12 row-owned router tests are the only bitwise router parity tests in the
  repo, and they are dark on every machine** — `MTPLX_ROW_OWNED_HARDWARE` is
  set by nothing. A further 306 router tests require M5/G17 + macOS ≥26.2.
- Session-bank capacity eviction is untested; `CacheMissReason.EVICTED` is
  never asserted anywhere.
- `_iter_prefill_chunks` / `_iter_prefill_chunk_spans` have no direct tests.
- `tests/test_expert_slots_runtime.py` is 7,651 lines / 124 tests and **0
  compare a number** — eviction is structurally tested only.
- `tests/test_expert_manifest.py:49` hardcodes
  `/Users/davidtai/.cache/huggingface/...`, so that test runs on one laptop.
- 15 tight wall-clock assertions are flaky by construction (tightest:
  `elapsed < 0.05`).

Worth protecting: rANS roundtrip, KV quant vs stock mlx_lm SDPA, speculative
cache parity, manifest byte-exact offsets, shadow-kernel numpy reference.

## Follow-up 2026-07-18 — measured, not assumed

**The Q2 fidelity floor is now grounded in data.** The fix initially pinned
`Q2_MIN_ROUNDTRIP_COSINE = 0.5` as a guess, explicitly flagged as unvalidated.
Measured on the shipped banks (24 experts sampled across all 79 layers,
dequantizing hy3-expert-only-mlx-q2 and -q4 via `mx.dequantize`):

    min 0.9112 | p10 0.9193 | median 0.9197 | max 0.9199

- The sibling Q4 converter's 0.99 floor would reject **24/24** legitimate Q2
  conversions. That bound cannot transfer to 2-bit.
- The distribution is tight, so the floor was raised to **0.85** — ~7% headroom
  under the observed minimum, while still catching real degradation. 0.5 would
  only have caught total collapse.
- Every artifact on disk clears 0.85, so enforcing it on read invalidates
  nothing existing.

**Two audit findings have now been refuted on direct inspection** (the q1 test,
and step3p5's MTP guard), on top of the earlier q4-checkpoint "anomaly" that
turned out to be two shard generations and the rans32x manifest that fails
closed on its own. Treat every `~` marker here as a hypothesis.
