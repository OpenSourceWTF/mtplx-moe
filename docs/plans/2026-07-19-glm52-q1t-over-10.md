**Goal:** Produce two exact 1024-input/1024-output GLM-5.2 Q1T depth-3 rows above 10 tok/s, below 96 GiB, with canonical token hash `4b0c1741123cad8d59f8a01dfb2d3e9f30c28eef9f97573aa14def0f75a92f31` and shared Qwen service restored after each exclusive run.

**Architecture:** Install one explicit `glm52-q1t-over10` execution lane at construction. The lane requires the validated lossless rANS sidecar, binds fixed-shape t158 projection callables from measured GLM AR/verify geometry, and uses a qualified direct captured-prefix committer with no boolean fallback, rollback, or re-forward path. Only logical assignment count may select a projection route during execution; model, codec, bank, shape, kernel, and capture-state checks happen before the retained measurement.

**Tech Stack:** Python 3.11, MLX/Metal kernels, pytest, Ruff, the existing exclusive-GPU/Qwen guard, and the issue #51 depth-matrix benchmark.

**Assumptions:**

- Assumes model key `glm52-expert-q1t`, base manifest digest `5017b201e858931cfeafa466a8173e685af8dfcd3a47679bccd491d6a7122dd1`, rANS artifact digest `7d055a1555551d5575183ad94c678c4e4c56fbb66488d009063dc6c1b7141e75`, Q4 MTP, depth 3, cache72, component banks, and the exact 1024/1024 seed-0 workload — it will NOT silently generalize to Hy3, GLM Q2, another codec, another depth, or another cache envelope.
- Assumes the geometry census confirms the measured AR and verify assignment shapes used by the fixed route table — the lane will NOT install if the retained workload can produce an unqualified logical M.
- Assumes the active verify-on rANS qualification reaches canonical parity before the verify-off headline run — hash verification will NOT remain in the measured read path.
- Assumes the existing optimized GDN capture backend passes exact cache/logit parity before installation — the lane will keep the qualified stock capture backend if it does not.
- Assumes the measured composite may still land below 10 tok/s — if it does, the implementation must return to design with the new profile and shape evidence before writing the fused t158 gate/up/SwiGLU contingency; no topology transplant is permitted.

- [x] **Step 3: Implement the minimal construction-plan primitive**

```python
@dataclass(frozen=True)
class CapturedPrefixCommitPlan:
    max_verified_tokens: int
    recurrent_commits: tuple[Callable[[list, dict, int], None], ...]
    trimmable_layers: tuple[int, ...]

    def commit(self, cache, captures, *, keep_tokens, verified_tokens):
        capture_index = keep_tokens - 1
        trim_tokens = verified_tokens - keep_tokens
        for commit_layer in self.recurrent_commits:
            commit_layer(cache, captures, capture_index)
        for layer_index in self.trimmable_layers:
            cache[layer_index].trim(trim_tokens)
```

`qualify_captured_prefix_commit(...)` validates final-only state, exact stock capture keys, layer ownership, state shape/dtype, maximum capture width, backend selection, and disabled detach policy once. It binds one straight-line stock state-slice callable per recurrent layer and the fixed trimmable layer indices. `keep_tokens` and `verified_tokens` remain runtime inputs because the accepted 1024-token baseline contained 288 four-token verify windows and one three-token tail window. The plan returns `None`; it has no eligibility or fallback result.

class Over10QualificationReceipt:
    schema: str
    base_manifest_sha256: str
    rans_artifact_sha256: str
    codec: str
    geometry_sha256: str
    capture_backend: str
    capture_depth: int
    token_sha256: str
    exact_capture_parity: bool
    receipt_sha256: str

    def require_for(self, actual: ConstructionFingerprint) -> None:
        expected = self.as_fingerprint()
