# MTPLX 2.10.0

Qwen 3.8 Flash-Next runs day-0 as a first-class model with its packs public on Hugging Face, long-context decode past 128k improves by up to +54 percent, the engine plans memory for the Mac it is actually on, reasoning effort works identically across the app, the CLI, and every API lane, agent tool calling loses two long-standing failure modes, the mlx floor moves to a measurably faster release, and KV-cache quantization goes from broken to usable — with the remaining gaps stated honestly.

## Qwen 3.8 Flash-Next, day-0

The 125B-A6B Qwen4-generation preview (GDN hybrid MoE, Qwen Sparse Attention, 32 GB n-gram memory sidecar) is a native MTPLX family from day one — not a compatibility shim. The in-tree backend is parity-exact against the reference implementation, the model's own MTP draft head runs through MTPLX's standard speculative lane, and the family got its own kernel campaign before release: the GatedDeltaNet decode step runs as a single Metal dispatch, verify blocks run a fused conv+SiLU+L2-norm kernel, and both defaults carry boot-triple A/B receipts. Measured through the real server on an M5 Max: ~61 tok/s autoregressive, 63–76 tok/s with the native MTP head depending on workload.

- Two packs, public on Hugging Face: **[Bare Speed](https://huggingface.co/Youssofal/Qwen3.8-Flash-Next-MTPLX-Bare-Speed)** (flat 4-bit, quickest) and **[Optimized Speed](https://huggingface.co/Youssofal/Qwen3.8-Flash-Next-MTPLX-Optimized-Speed)** (dynamic 4-bit with 8-bit attention, higher quality, recommended). The n-gram sidecar streams from SSD by default, so both fit 96 GB+ Macs with headroom.
- The streamed sidecar is honest in the accounting now: the memory plan, session-bank budget, and the app's Memory Detail card report it as `29.8G streamed from SSD (not wired)` instead of counting it as weights — which had produced a false "MODEL DOES NOT FIT", a 30 GB-pessimistic context window, and a 30 GB-starved session bank on 128 GB Macs. A hot-row LRU (`MTPLX_NGRAM_HOT_MB`, default 1024) keeps decode-sized gathers in RAM, byte-identical by test: +5–10 percent AR and +7.5–16 percent MTP decode over the prior streamed behavior at identical memory.
- Reasoning effort has full parity with the 27B: the same `xhigh`/`medium`/`low` levels in the app's picker, `--reasoning-effort` on the CLI, and the `reasoning_effort` request field — family default `xhigh`. Previously the family silently discarded the field and always thought at maximum.
- Both appear in the app's model picker and first-run onboarding on machines that fit them, right behind the 27B trio, and in the CLI catalog — with the family's own serving contract (temperature 1.0, adaptive draft depth, batched verify) applied end to end. No "unverified" badge, no manual config: the packs ship with a measured runtime contract.
- One numerics note, stated honestly: this family verifies through the generic batched lane for now (its GDN internals do not yet expose the capture-commit verifier the 27B rides, which measures 6/6 token-exact MTP-vs-AR at temperature 0). On Flash-Next a rare near-tie argmax under greedy decoding can differ from single-step decode — observed once in 192 tokens in the release gate, with both continuations converging. The speculative acceptance math itself is unchanged and exact; the family-native capture verifier that closes the gap is in progress.
- New for every family: `mtplx forge verify --stamp` boots a model on the real serve path, measures it, and writes its runtime contract in place — the step that turns a family-compatible-but-unverified folder into a verified model without rebuilding or copying anything.

## The engine plans memory for your Mac

MTPLX no longer assumes a 128 GB studio machine (issue #305 and friends). At startup the serve banner prints the machine plan — engine budget, weights, the resolved context window, session-bank budget — and the default context window is the largest one whose full-window KV actually fits: a 48 GB Mac serving the Speed model resolves ~200k tokens instead of a physically impossible 262,144, with a loud note instead of a silent swap-death. 128 GB machines are unchanged.

- The session bank yields dynamically as a long-context request's KV grows, ahead of any swap; macOS pressure plus an earlier allocator-relative signal drive the shedding guard.
- Metal allocation failures now shed caches and answer a structured 507 instead of crashing the daemon and leaving the next request to hit the same wall (issue #348 class).
- `/health`, the dashboard, and the app carry the plan, guard events, and a pressure banner. `--memory-budget 48G` reproduces a real 48 GB seat exactly.

## Long-context decode past 128k, improved

Past 131,072 prompt tokens the engine silently repaged dense decode into a cache layout that structurally excluded the packed verify kernel: verify fell onto a lazy fallback paying roughly 30x its normal round cost, and speculative decode collapsed to plain-AR speed. On an M5 Max 128 GB at 147k context, decode measured 12.0 tok/s before the fix and 16.3 after — 18.4 with prompt-copy speculation off.

- The dense-decode ceiling is now memory-aware: `MTPLX_SUSTAINED_DENSE_DECODE_MAX_CONTEXT=auto` budgets 15 percent of device RAM against the model's KV bytes per token, clamps to the model's context window, and floors at the old 131,072 literal so no smaller machine regresses.
- The resolution is announced once in the serve log, including whether the model supplied its own KV geometry (`MTPLX_DENSE_KV_BYTES_PER_TOKEN`) or fell back to the Qwen3.8 default.
- Operators can still pin any numeric ceiling, and an exported env now beats the profile instead of being silently stomped back.

## Faster stack: mlx floor raised to 0.32.2

A clean same-wheel A/B on an M5 Max measured mlx 0.32.0 → 0.32.2 at +29 percent decode and +41 percent prefill at 88k context, and +31 percent at 16k. The dependency floor moves to `mlx>=0.32.2` so existing installs converge on the faster stack instead of sitting on 0.32.0 forever. New pin-guard tests fail loudly if an environment or a shipped profile ever drifts below the receipted stack again.

## KV-cache quantization: from broken to usable

Honesty first: q8/q4 KV quantization was effectively broken. Turning it on crashed serving at warmup, and before that bug existed it could cost half your decode speed. 2.9.3 replaces the lane:

- The warmup crash is fixed.
- q4 now routes through the exact packed-quant kernel via a persistent quantized bank instead of re-dequantizing the entire prefix every round.
- The compiled verify bank now promotes quantized paged caches instead of dropping every verify round to eager execution.
- A pre-existing q4 numerics defect at head_dim 128 is fenced fail-closed; the shipped model family (head_dim 256) is exact.

Measured cost at 16k context on an M5 Max, versus quantization off: q8 about −4 percent decode, q4 about −19 percent — down from crash / −50 percent. That is not yet the zero-loss bar we hold ourselves to, so the toggles stay opt-in: q8 is a fair trade today for 2x context headroom, q4 is for capacity emergencies. One known limit we are still working: past the dense-decode ceiling, quantized decode still drops onto a slow routing lane; the cause is located and the fix is in progress for a follow-up release.

## See what the engine actually did

The decode cliff hid for months because fast lanes declined silently. That class of blindness is closed:

- Every request row now records packed-route bail counters and paged-adapter engagement, so a lane that stops engaging shows up in the request log instead of only in a benchmark weeks later.
- `MTPLX_ROUTE_DEBUG=1` prints one line per layer naming the attention branch taken and every gate input.
- Warmup failures log their full traceback instead of a one-line skip.

## Fixed

- The compact tool contract no longer drops trailing tools (#376, adapting community PR #379 by @ArctifoxNL). Over its 1200-character budget the "Declared tools" line was raw byte-cut, deleting whole tool names at the tail — `task` first in Claude Code-shaped toolsets — and the contract's own "never invent an undeclared tool" clause then made the model treat every dropped tool as nonexistent, killing subagents. Every declared name is now kept; only per-tool signature detail is shed.
- Cancellation errors name their real cause (#381). The shared per-request cancel flag is tripped by several unrelated paths, and the terminal frame blamed every non-disconnect trip on `POST /v1/mtplx/cancel` — an endpoint nobody called. The first origin (explicit cancel, client disconnect, stop sequence, tool-call finalization, stall watchdog, teardown) is now recorded and reported in the frame and the metrics.
- Streaming agent turns no longer die with a fabricated `request cancelled via POST /v1/mtplx/cancel` error (#332, #343). After a complete streamed tool call the server cancels its own generation to end the turn; when the worker's acknowledgement took longer than the stream loop's 250 ms poll, the loop misread its own cancel as a foreign cancel and killed the healthy turn with that error — nobody ever called that endpoint. Tool-calling streams now drain until the worker acknowledges and end with the proper `tool_calls` terminal frame. Real cancels and real disconnects behave exactly as before. This hit tool-calling agents (Pi, OpenCode-class clients) and got more likely on slower machines and longer contexts; plain streaming was never affected.
- The dynamic-offset paged verify kernel had never compiled since its introduction (a pointer-cast Metal bug hidden behind its own mask gate) and crashed at q_len above 5 once compiled; both are fixed. The kernel stays behind its opt-in gate pending a serve verdict, but the crash class is gone.
- A model that ships without KV-geometry metadata now shows itself in the serve log instead of silently mis-budgeting dense decode.
- Long prefills no longer look like a dead connection (#358): streaming endpoints emit a `: keep-alive` SSE comment every 5 seconds until the first token, so strict client and proxy read-timeouts (Claude Code, Cursor, Open WebUI, nginx, cloudflared) stop dropping healthy requests mid-compute. Off with `MTPLX_SSE_HEARTBEAT=0`.
- SSD session-cache writes no longer starve on an idle server, and a clean shutdown flushes what is pending (#290) — a killed daemon stops costing a full re-prefill of sessions that were already computed.
- Unexecuted tool calls are no longer silently swallowed (#349): when a client asks about files and the model emits tool markup the server cannot execute, the chat now shows a truthful notice instead of nothing.
- The app accepts custom Hugging Face models the engine reports as runnable (#359); "can this build construct the model" is now the single question, answered by the engine, not by the presence of an `mtplx_runtime.json`.
- Each conversation streams on its own turn stream in the app (#324): switching conversations mid-generation no longer cross-wires or stalls either turn.
- Explicit performance settings are honored over client-target defaults (#325), and the native Chat launch target stops silently ignoring "Handle multiple at once".
- Forge routes official NVIDIA Nemotron-H configs correctly by deriving the MTP pattern from `mtp_layers_block_type` (#341).
- The update dialog's release notes are readable in dark mode (#367) — this page included.
- `mtplx serve` launched from a directory containing an `mtplx/` folder (a source checkout, a vendored copy) silently ran that folder's code instead of the installed release. Every daemon and tool child now starts Python with `-P`, so the launch directory can never shadow the runtime.

## Experimental, off by default

- `--scheduler-mode hyper`: the single-user manufactured-concurrency chassis (H0). Trajectory-sha-identical to serial in every gate pair.
- `MTPLX_NAX_TILE_ROUTE`: the first M5 tensor-unit (Neural Accelerator) attention kernel at decode shapes — +34 to +45 percent over the scalar wide-QL kernel at QL9 in gated walks.
- `MTPLX_ADAPTIVE_DTEMP`: acceptance-EMA adaptive draft-temperature controller.
- `MTPLX_CCOPY_BANK_ROUTE`: copy-speculation dispatch through the compiled verify bank.
- `MTPLX_PAGED_TAILMASK_ELIDE`: the resurrected paged kernel's mask-elide fast path.
- `MTPLX_FORKEV_TELEMETRY`: shadow pricing for speculative fork expected value.
- `MTPLX_QSA_FLASH`: block-sparse flash-skip lane for Qwen Sparse Attention decode; long-context verdict pending.
- `MTPLX_NGRAM_RESIDENT=1`: wire the full n-gram table in RAM (bench pin for 160 GB+ machines; the streamed default meets or beats it in the product register).
